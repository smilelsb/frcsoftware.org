## Syntax（语法）

Syntax（语法）是一门语言中所有程序都必须遵守的基本规则。
它与写作类似。
在写作中，句子的第一个单词必须以大写字母开头，并且所有句子都要以句号结尾。
Java 的语法非常严格，不同类型的代码行有各自的书写规则。
Syntax errors（语法错误）是最常见的一类错误。
每当提到语法时，都要仔细留意。

## Variables（变量）

Variables（变量）是程序中用于存储信息的容器。
变量可以保存温度，也可以保存电机速度。

创建一个变量需要 5 个部分：

1. 数据类型
2. 变量名
3. 等号
4. 变量的值
5. 分号

### Data Types（数据类型）

Data types（数据类型）指变量所保存的值的类型。
它告诉程序该变量保存哪种信息，以及可以如何使用。
与 Python 等某些编程语言不同，Java 中的每个变量都必须有类型。
这会让程序更可靠，并帮助避免一些常见错误，因为 compiler（编译器）会在类型使用错误时报错，从而阻止这种用法。

FRC 编程中常用的一些数据类型包括：

- int：可以表示正数或负数的整数。
  int 只允许不带小数的数字。
  示例：12
- double：可以表示正数或负数。
  与 int 不同，double 允许小数。
  示例：34.1
- boolean：值为 `true` 或 `false`。
- String：保存一串字符。
  使用双引号（"）表示。
  示例：“Hello World”

<Aside type="note" title="Note（备注）">
    创建 String 时，务必把 S 大写！ `string robotName = "Plunk"` 会报错，而
    `String robotName = "Plunk"` 则不会。
</Aside>

### 名称

在 Java 中，变量名只能由字母、数字和下划线（`_`）组成，但不能以数字开头。
变量名可以由你自行决定，但建议让名称具有描述性且易于阅读。
这样既能帮助你理解自己的代码，也便于他人提供帮助。

一种常见的变量命名风格是 camel case（驼峰命名法），除第一个单词外，其余每个单词的首字母都大写。
例如，`frontLeftDrive`、`currentTemperature` 和 `targetPosition` 都使用驼峰命名法。
另一种常见风格是 upper snake case（大写下划线命名法），每个单词全部大写，并使用下划线分隔。
例如，`BACK_LEFT_DRIVE` 和 `GEAR_RATIO` 都使用大写下划线命名法。

为机器人编程时，通常使用驼峰命名法创建变量。
大写下划线命名法用于 constants（常量），也就是定义一次后不再更改的变量。

<Aside type="note" title="Note（备注）">
Java 是一种 case-sensitive（区分大小写）的编程语言！
这意味着大写字母和小写字母会被视为两个不同的内容。
例如，MotorID 与 motorID 不同。
即使拼写看起来相同，如果变量名是 MotorID，之后却写成 motorID，Java 也会把它们视为不同的名称，代码因此会报错。

</Aside>

如前所述，建议让它们具有描述性且易于阅读。

### Semi-colons（分号）

在 Java 中，semi-colons（分号）`;` 类似于句子中的句号。
它告诉编译器一条 statement（语句）在哪里结束。
在大多数情况下，行尾缺少分号都会导致错误。

## Comments（注释）

编程时，我们使用注释写下说明代码作用的笔记。
这能让代码对其他人更易读，因为他们不确定代码的作用时，可以阅读注释。
写注释对你自己也有帮助！
留下解释代码作用的注释，有助于理解代码，也有助于调试。

编译器会忽略注释，因此也可以用注释阻止代码运行。
在 Java 中，注释有两种：单行注释和多行注释。

### 单行注释

单行注释以 `//` 开头，并把该行剩余部分标记为注释。
例如，下面的代码在打印语句前留下了 “This prints out Hello World.” 这条说明。

```

```

两个示例完成的是同一件事，没有区别。
把注释放在代码前面还是同一行，取决于哪种方式对你的代码最合适。

### 多行注释

多行注释以 `/*` 开始，以 `*/` 结束。两者之间的文本或代码都会变成注释。
当有许多行文本，或需要把大量代码变成注释时，通常使用多行注释。
例如，下面是一段包含两行文本的注释。

最好用注释以文字说明代码要完成的任务，而不是仅仅重复代码本身。
例如，下面是一条有用的注释，因为它说明了目的以及代码如何完成该任务。
